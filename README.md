# Интервью frontend: реестр заявок CRM

Практическое задание для jun+ / middle: формы, таблица, серверные данные, фильтры в URL и постепенная загрузка. React + TypeScript + Ant Design + RTK Query. RTK Query настроен; библиотеку форм кандидат выбирает сам.

## Локальный запуск

Нужен Node.js 22.18+ или 24+.

```sh
npm install
npm run dev
```

Откройте адрес из терминала. Проверки: `npm test` и `npm run build`.

## Что уже работает

84 заявки, таблица, первая страница из 12 элементов, фильтры в памяти, просмотр карточки, обработка ошибок чтения и защита чтения от устаревших ответов. Кнопка «Обновить» повторяет загрузку. Кнопка 503 ломает следующий запрос. «Сбросить данные» возвращает исходные записи.

## Формат интервью — 60 минут

10 минут знакомства, 10 минут обсуждения подхода, 25 минут кода и проверки, 15 минут разбора. Основная задача — форма изменения заявки и актуализация карточки/таблицы после сохранения. Кеш нескольких выборок, URL и бесконечная прокрутка обсуждаются после практики. До начала можно заменить основную задачу на URL или догрузку; все три сценария одновременно не требуются.

Мок хранит данные в памяти вкладки и сбрасывается при перезагрузке. Общие ссылки проверяют восстановление фильтров, а не совместное изменение записей.

## Структура проекта

```text
src/
  app/                         # провайдер Ant Design, тема и общие стили
  pages/tickets/ui/            # сборка экрана, загрузка и связь частей
  features/filter-tickets/ui/  # панель фильтров; альтернатива — URL
  features/edit-ticket/ui/     # заготовка редактора; основная задача — форма
  entities/ticket/api/         # контракт и мок заявок, тесты
  entities/ticket/ui/          # таблица заявок на Ant Design
  main.tsx                    # точка входа
```

Это базовая FSD: app → pages → features → entities. Внешние импорты слайсов идут через их `index.ts`. Соседние features друг от друга не зависят: их связывает страница. Слои widgets и shared пока не нужны. API-мок содержит типы и справочники маленькой предметной области; при росте их можно выделить в model. Задание не требует знания FSD по памяти.

Ant Design уже настроен и локализован: Table, Input, Select, Card, Alert. Для формы можно взять Form Ant Design или знакомую библиотеку. Кандидат дорабатывает поведение, а не переносит компоненты между слоями.

## Серверные данные

`src/app/store.ts` подключает reducer и middleware RTK Query. `src/entities/ticket/api/tickets-api.ts` содержит готовые `getTickets`, `getTicket`, `updateTicket`. Публичные хуки экспортируются из `entities/ticket`, отдельный `entities/ticket/api.ts` — публичная точка входа слоя API для store без импорта UI.

Список получает `{ filters, cursor }`; первая страница уже работает. В странице используем `currentData`, чтобы не показывать данные предыдущих аргументов. Кнопка «Обновить» повторяет только запрос списка. «Сбросить данные» сбрасывает мок и кеш.

Основная практика — форма с `useUpdateTicketMutation` и актуализация данных. URL и догрузка — альтернативные задачи или вопросы для обсуждения. Теги, инвалидация и накопление страниц намеренно не настроены. Допустимы infinite query или запросы отдельных страниц с обоснованной организацией результата; писать собственную кеш-библиотеку не требуется.
